# 配布一覧・検証ログ・出力構造の契約を固定する

## 背景と仮説

[Issue #1](https://github.com/Mr-Kondo/science-review-design/issues/1) の比較調査を受けた改修。ユーザーは既存設計に基づく4観点の整理と、本設計案、レビュー・リリースまでの実行を承認した。

- 仮説思考：配布ファイルを明示すれば、スキル内に追加した私的ファイルの混入を防げる。指定構造の最終照合は、科学判断を変えずに出力契約への適合を保てる。
- 要件・先行調査：mece-cluster-advisor の追跡ファイル限定を参考に、Git不要の展開アーカイブでも使える一覧方式を選ぶ。official-prompt-tailor と japanese-readability-editor のAntigravity配置・探索先外バックアップ、後者の指定見出し保持を採用する。
- README駆動：READMEに配布内容、4つのtarget、バックアップ、保存先、PowerShell実行例と検証限界を先に定義する。
- ドメインモデル：配布元＝一覧に載ったファイル、管理対象＝版とハッシュを持つ配置、バックアップ＝探索対象外の旧配置、評価＝固定入力・条件・判定、通常の監修成果＝依頼時のみ保存、と分ける。

## 決定・実装計画

追加依存なし、Python 3.10以上。`tools/package-files.json` に相対パスの一覧を保持し、`tools/install.py` は一覧以外を走査・配布しない。絶対パス、親参照、重複、リンク、欠落、許可外の場所・拡張子、私的な名前は拒否する。Git追跡一覧との一致は開発テストで検査し、配布時はGitを要求しない。

`--target` は codex / claude / antigravity / antigravity-cli / all。ユーザー配置は順に `.agents/skills`、`.claude/skills`、`.gemini/config/skills`、`.gemini/antigravity-cli/skills`。プロジェクト配置はClaudeが `.claude/skills`、他は `.agents/skills` とし、重複先を一度だけ処理する。ホスト固有の引数展開へ依存せず、自然文入力を受ける。

更新前に既存のハッシュ検査を行い、探索先の外（各 `skills/` の親の `science-review-backups/`）へ旧配置のコピーを保持する。バックアップ失敗なら置換しない。変更済み・未管理・リンクの配置を勝手に取り込まない。既存の置換失敗時の復旧処理を維持する。

生ログはルート `feedback/` へ移し、公開用の匿名ケース・採点概要は残す。旧ログは削除せず移動し、移動先はGit対象外。`SKILL.md` は指定見出し・列・残す節の照合だけを補強し、事実・不確実性を削らない。構造ケースと科学判断の代表ケースを同条件で変更前後比較する。
ignoreの `feedback/` は全階層に効かせ、検証結果の混入を防ぐ。Antigravityの配置先は2026-10-31に比較先2スキルのインストーラーとMacのディレクトリ構成から採用した慣例であり、IDE/CLIでの実読込確認ではない。

既存の3 OS unittestには日本語・空白・UTF-8が含まれる。説明書内の識別したPowerShellコードブロックをWindows CIでそのまま実行し、二重のテスト体系を作らない。

汎用の評価準備・集計ツールは今回は見送る。現行手順にはハッシュ・実行条件・未確認の記録があり、繰り返し頻度と実際の欠測が不足。3回以上の評価で同じ準備ミスが再発するか、手動準備が評価時間の20%以上になれば再検討する。今回の比較用スクリプトは `feedback/` に限定する。

## 成功指標・撤退条件

- [x] 私的Markdown・未追跡JSONが配布されず、clone/アーカイブの配布内容が一致する。
- [x] 4 targetの配置、更新、削除、旧配置の保持、変更保護、失敗復旧のテストが通る。
- [x] `feedback/` はignoreされ、追跡ファイルがなく、既存ログが移動前後で一致する。
- [x] 構造ケース3件と科学判断の代表ケースで、同条件の前後比較に重大な境界違反・科学的回帰がなく、指定構造を満たす。少数例の確認であり一般的精度とはしない。
- [ ] 説明書のPowerShellブロックがWindows CIで成功する。
- [ ] リリース版をMacの該当配置へ反映し、配布一覧の各バイトを照合する。

配布漏れ・復旧失敗はリリース停止。科学判断の回帰や構造不適合が残れば指示を再検討し、結果を隠して再試行しない。モデル・OSの検証不能は未確認としてIssueへ残す。

2026-10-31の限定比較では構造適合は変更前後とも3/3、科学代表3件の主要判断に回帰なし。ST02の冒頭判定と後段訂正の不整合、ST03の未出典性能値は全条件で残り、改善は示せなかった。同じ失敗の再試行を停止し、[Issue #2](https://github.com/Mr-Kondo/science-review-design/issues/2)で追跡する。詳細は[評価記録](../.claude/skills/science-review/evals/verification-results.md)を参照。

## 非機能要件と機会費用

秘密・個人情報・未公開原稿は評価に使わず、匿名の合成ケースのみを使う。ログは公開しない。外部レビューへ渡すのは公開予定のコード差分と合成入力のみ。新規ライブラリ・ライセンス変更はない。追加のモデル実行は限定セットに留め、使用モデルと回数を記録する。簡易出力・指定構造を尊重し、不必要な表や長文化で読みやすさを損なわない。

一覧の保守、バックアップのディスク使用、WindowsのCI時間が増える。バックアップは自動削除せず、利用者が確認して管理する。通常利用の自動保存、description変更、科学ライブラリ追加、既存評価92実行の全面再実行は対象外。READMEの変更と本ADRの整合を最終確認する。

## 代替案

- 再帰走査＋除外：保守は容易だが未知の私的ファイルを除外しきれない。
- Git追跡限定：開発時は有効だがGitなしの配布を損なうため、開発検査だけで用いる。
- 全評価基盤の新設：既存手順と重複し、今回の規模では費用に見合わない。

## レビュー

背景・比較案・変更先・成功指標・撤退条件・非機能要件を記載。仕様の実装可能性を点検し、独立したコードレビューと実行結果をIssue/PRに追記する。将来判断を変える場合は新ADRから本記録を置き換える。
