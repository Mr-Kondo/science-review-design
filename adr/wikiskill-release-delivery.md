# WikiSkill検証の変更をリリースし配置まで完了する

## 文脈と要件

Issue #4、PR #5の更新用索引・有限比較ツールはマージ済み。候補不採用を理由にリリースを省略していたが、ユーザーは内容変更があればリリースし、その後に後片付けすること、および「最後まで」にリリースを含むことを明示した。
既存の設計承認と通常サイクルを引き継ぎ、有限比較の結果を変更せず配布を補完する。旧ADRの採否は維持し、版・リリース省略の判断だけを置き換える。

## 決定とREADMEへの反映

配布・更新用ツールの変更をパッチ版2.1.1としてリリースする。インストーラーの版を上げ、科学判断手順と35ファイルの配布一覧は変更しない。
READMEの版・バックアップ運用と結果記録の当初判断を整合させる。これは科学品質改善の仮説ではなく、リリースと配置の完了条件の訂正である。

既存のインストーラー・版管理・ハッシュ照合を再利用し、新たな配布基盤は作らない。比較対象だったscience-review、official-prompt-tailor、mece-cluster-advisorの構成調査は旧ADRを参照する。新規スキルではないため構成の作り直しや数値閾値の移植は行わない。

## 成功・停止条件と手順

1. 既存検査・独立Claude Codeレビュー・CIを通し、PRをマージする。
2. マージ済みコミットを指すv2.1.1タグとGitHub Releaseを作成し、対象を照合する。
3. 既存MacのCodex・Claude Code・Antigravity・Antigravity CLIをインストーラーで更新する。関連する既存の別配置があれば確認する。
4. 各配置の管理情報が2.1.1であり、配布一覧の全35ファイルとソースがハッシュ一致することを確認する。
5. 成功後に今回作成したバックアップ・一時資源・マージ済み作業ブランチを削除し、Issueを閉じる。元の評価証拠は非追跡で保持する。

リリース対象不一致、CI失敗、配置のローカル改変や照合失敗時は停止して根拠を記録する。配置失敗時は復旧用バックアップを削除しない。未知原稿の再評価や追加モデル回答で採用判断を救済しない。

## 非機能要件と機会費用

標準ライブラリと既存gh・Claude CLIだけを使い、新規依存・ライセンス変更・有料サービス追加はない。生ログ、接続情報、端末固有パスは公開しない。追加モデル呼出はこの小差分のコードレビュー1回に限定し、評価回答は増やさない。
三環境の配置形式を維持するが、実アプリ起動やモデル品質の同等性を主張しない。新たな画面はなくアクセシビリティへの変更はない。
内容を変えずタグだけ付ける案は版と既存Mac管理情報を区別しづらいため見送り、既存インストーラーのパッチ版更新で届ける。運用上の検査・配布コストは増えるが、ユーザー指定の完了範囲に必要である。
