# 監修：主張と条件を切り分ける

## 主張の抽出

C01…ごとに、対象の位置（ファイル・節・行、貼付なら段落）、短い引用または要約、話者、資料の格、種類を記録する。種類は現実科学／工学／独自則／比喩／数値／能力など。断定に見える台詞でも、人物の認識か作者の説明かを先に確認する。

一文に「未知物質を出現させ、その熱で発電し、一晩送電した」とあれば、出現の独自則、熱変換、発電量と需要、送電の条件に分ける。独自則の許容範囲が他の工程へ漏れないようにする。全作品で超常が材料だけを供給すると仮定せず、対象作品の定義を読む。

比喩・俗称・演出だけなら厳密な等式と扱わない。ただし比喩を定量結論の根拠に接続していれば、その接続を点検する。人物の誤解が意図的でも、地の文が同じ内容を現実の事実として断定すれば別の主張として扱う。

## 資料と対象の固定

ファイル対象は元のバイト列のSHA-256、確認日時、可能ならGit HEADと対象パスの変更状態を記録する。Gitなしでも開始する。貼付本文は受領テキストのUTF-8を基準にし、改行の変換などがあれば示す。

技術名と同義語を `rg` で指定資料ルートから探す。対象ファイルの外に製作主体・性能・制約がないか確認する。検索語、範囲、参照箇所を残す。関連箇所を読むことと、別章全体を監修対象へ増やすことを区別する。

保存だけを依頼された場合も対象本文は編集しない。作業後にハッシュを照合し、変化があれば差分を調べる。並行する作者の編集を自分の変更と決めつけない。

## 各軸の問い

| 軸 | 問いと判定の境界 |
| --- | --- |
| A 科学 | 適用される法則、モデル、式、量、数値は根拠と一致するか。支持は条件と確認範囲に限る |
| B 工学 | 材料・電源・時間・設備・接続・計測・制御・排熱・反作用・補給の関連条件が充足するか |
| C 作品内 | 作者確定の法則、資料の優先関係、時点、能力上限と整合するか |
| D 実行能力 | 知る／設計／製作／既製品利用／現場制御の必要な各段階に根拠があるか |

原理に反しないだけでは、所定のサイズ・出力・応答時間で動く証拠にならない。製作、購入、再利用を分け、装置間の接続条件と使用環境を確認する。仕様を満たすかと、目的の利用に適するかは別の問いである（手法の由来はdesign-sourcesのM04）。

AIの演算速度が高くても、センサーが取得していないデータは得られない。観測から複数の原因が成立する逆問題では、追加の測定・実験・事前仮定が必要。学歴・所属だけでは全設備へのアクセスや製作能力を認定しない。

使用・習得時期が論点ならCの時系列とDの必要段階を別に評価する。未習得の技術を単独で使う矛盾があっても、設計・製作など関係しない段階まで矛盾としない。

## 情報不足・条件不足・誤り

- 適用される方式とモデルが分かり、必要条件を導ける：B「追加条件が必要」。条件を具体的に列挙する。
- 方式・主要入力がなく、どのモデルを使うか選べない：A/B「情報不足」。必要な値・資料を示す。
- 確認した条件下で法則・収支・算術に反する：A「誤り」、Bなら「条件矛盾」。証拠を示して明確に判断する。
- 確定した独自法則にだけ依存する：適用範囲に限り「独自前提」。現実工程を同じ判定へまとめない。
- 未確定の独自法則が必要：条件付き／情報不足、C「未確定依存」。採用を前提とする場合は条件文で書く。

未記載と不存在、未実施と未確認を区別する。確認できない外部出典に依存する判断は暫定／保留にし、未確認事項を正常と数えない。

## 衝突と修正

正典同士の衝突は双方の位置と適用時点を示す。作者が優先関係を指定していなければ統合しない。確定本文とメモの相違は格を示し、直ちに正典矛盾としない。

F01…は重要度順に並べ、位置、観察、E/K/設定位置、結論への影響、未確認事項、最も合理的な解釈、修正案、負担を記録する。同じ原因で複数のCを指摘するときは、一つのFから複数のCへ対応させてよい。件数を重複して数えない。

第一に物語の結果を保つ説明修正、次に既存条件の明示、必要なら新条件・新設定、最後に結果変更を検討する。この優先順は本スキルの設計上の提案。追加説明の量、関連資料の同期、物語のテンポや別設定へ及ぶ負担も添える。採用を作者に委ね、依頼外の改稿は行わない。
