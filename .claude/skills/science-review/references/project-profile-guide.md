# 作品プロファイルの読み方

Markdownの補助文書であり、専用パーサーや必須設定ファイルではない。指定された文書を読み、必要ならREADME・本文で補う。空欄は未指定。スキルが作者の世界法則を作らない。

優先関係は作者の指定と確認した本文で決める。ファイル名、フォルダ番号、更新日だけで正典を認定しない。確定事項、提案、人物の認識、AIメモ、舞台裏を分け、相反する確定資料は双方の位置を示す。

| 状況 | 扱い |
| --- | --- |
| プロファイルなし | 読める対象でA/Bを開始。創作ならCの判断できない点は情報不足、非創作なら対象外 |
| README中心 | 作者が明記した資料種別・参照ルールを使用。READMEの古さや本文との衝突を示す |
| Gitなし | 内容SHA-256と確認日時を使う。HEADを捏造せず、作業を止めない |
| 貼り付け本文だけ | 段落位置と受領テキストのハッシュで記録。ファイルを要求しない |
| 複数作者 | 共通の確定基準と指定の承認権限を確認。多数意見やAI案で勝手に確定しない |
| 正典の衝突 | 作者の優先指定があれば適用。なければ両位置を提示し、独断で統合しない |
| 古いプロファイル | 現在の本文を照合。旧指定の意図は断定せず、差分と必要な確認を示す |
| 時点未指定 | 習得・設備導入前後などの条件付き判断。判定不能なら時点の不足を示す |
| 未完成のアイデア | 未定を設定矛盾と扱わず、仮置き・提案のまま相談を進める |

実行主体の専門性は知識・設計・製作・利用・制御を分ける。AIや組織の支援には観測データ、設備、人員、予算、利用権、利用可能な時点の根拠が要る。実在の経歴は必要な専門性へ抽象化し、取得禁止資料を読まない。

超常法則は適用範囲、代替する工程、代償・制約、現実科学へ戻る工程を読む。供給や加工の役割を作品間で固定しない。演出の厳密さは提案の選び方に反映し、現実科学の誤りを正しいと認定する理由にはしない。

作成を頼まれたときだけassetsのテンプレートを用い、確認済み事項と未指定を分けて保存する。作者の未採用案を埋めて確定文書を作らない。
