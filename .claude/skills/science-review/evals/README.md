# 評価と利用

共有本体は `.claude/skills/science-review/`。Codex用の `.agents/skills/science-review/` は共有本体への相対リンク。コピーして使う場合もこの対応を保つか、Codexでは本体を `.agents/skills/science-review/` へ配置する。グローバルインストールは行っていない。

## 利用例

Codexでは、この作業フォルダのスキルを認識したセッションで次のように呼ぶ。認識されない場合は新セッション／再起動で確認する。ファイル配置の成功を起動成功と呼ばない。

```text
$science-review 「質量80 kg、速度10 m/sなら運動エネルギーは4.0 kJ」を簡易に検算。
$science-review chapters/scene-03.md の冷却装置。第2章の時点。設定は world/review-profile.md。排熱と電源を中心に標準レポートで確認。
$science-review notes/engine.md を詳細に監修。レポートと計算は reviews/engine/ に保存。対象本文は編集しない。
$science-review 体の廃熱で小型装置を動かすアイデアを相談したい。成立条件と、科学的に筋の通る代替案を比較して。
$science-review この考察の前提と結論のつながりを確認し、他にありうる説明も示して。
```

Claude Codeでは同じ文の先頭を `/science-review` にする。作品プロファイル・完成原稿は必須ではない。未指定条件は仮置き・提案として扱う。保存は指定された場合だけ、本文編集は明示的な編集依頼の範囲だけ行う。

## 実行できる検査

プロジェクトルートから実行する。Python 3.10以上、第三者ライブラリは不要。

```sh
python3 -m unittest discover -s .claude/skills/science-review/tests -v
python3 .agents/skills/science-review/scripts/dimcheck.py eq J 'kg*m²/s²'
python3 .agents/skills/science-review/scripts/dimcheck.py conv 36 km/h m/s
```

testsはCLIの終了コード、数値許容誤差、不正入力・資源上限、意味の異なる換算拒否と、パッケージの構成・JSON ID・fixture・参照の整合を検査する。frontmatterは標準のname・descriptionとmetadataのargument-hint。Claude固有のトップレベルargument-hintをmetadataへ移したので、補完ヒントの表示は保証しない。

形式検査はモデルの監修品質を評価しない。Pythonテストは物理モデルを認証しない。結果・環境・コマンド・未実施項目は [verification-results.md](verification-results.md)、公開用の採点・ハッシュ・実行概要は [extended-results.json](extended-results.json) を参照する。

## 事前固定した評価入力

[cases.json](cases.json) は監修16件＋相談4件。[trigger-cases.json](trigger-cases.json) は肯定10件・近接否定10件。全fixtureは匿名の合成作品・説明。原稿・実在の経歴を使わない。出典403のケースは合成状態で、実際のHTTP取得や論文として扱わない。

期待判断・禁止挙動・採点観点はモデル実行前に固定する。実行時のcases/trigger/fixture/skillのSHA-256を記録する。評価モデルへ渡すのはprompt、指定fixture、必要なスキルだけ。正答・禁止挙動・採点表は評価者に留め、モデル入力へ混ぜない。

## モデル監修と起動は別評価

1. 一時領域にfixtureをコピーする。利用者の実原稿で試さない。ケース15だけ指定レビュー先に出力を許可する。
2. スキルあり／なしで、同一モデル・同一prompt・同一fixture・ツール条件を使用し、別セッションで実行する。モデル・CLI版・正規オプションを記録する。
3. スキルありはCodexの `$science-review` ／Claudeの `/science-review` を使い、読込ログとSKILL.mdの実読込、必要な参照の使用を確認する。名前に応答しただけでは起動成功としない。
4. 代表8件SR01/03/04/08/11/15/17/19を各3回、スキル有無で繰り返すのを目安とする。全20件を評価できたか、代表のみかを記録する。
5. 最終回答とツールログ、経過時間、出力量、実使用モデル、スキルハッシュ、ケースごとの0/1/2採点、禁止挙動、ばらつきを保存する。
6. ケース15は保存したレポート・入力・スクリプトを再読し、再実行する。全ケースでfixtureの前後ハッシュを比較する。変更されたスキルを評価済み版と混同しない。

読込確認は終了0のファイル読取と実際の出力で照合する。SKILL.md本文、補助参照、明示呼出しを別項目にし、補助参照だけの読込から本文の読込を推定しない。自動展開がコマンドログに残らなければ、その本文読込は未確認とする。
複数ファイルをまとめた読取で他ファイルの失敗があった場合は、本文の出力を観測できたこととコマンド成功を分ける。Claudeのネイティブ展開も、展開された本文そのものが記録されている場合だけ確認済みとする。

起動評価はtrigger-casesの自然文を、**明示呼出しなし**で新セッションへ与え、スキルの実読込をログで判定する。文の分類だけをモデルに答えさせた結果は実際の選択率ではない。スキルなし条件では同名スキルがないことを確認し、個人用の重複があれば混入として記録する。

ネットワーク・モデル権限などで失敗したら、その状態とコマンド・ログを記録し、実装とローカル検査は完了させる。現在の作成会話での自己点検を独立評価としない。
失敗した試行を成功率の分母へ黙って混ぜたり、再試行で上書きして消したりしない。改訂前の比較と最終版の検査は別集計にし、旧版の正答率を最終版へ移さない。全ログ・端末パス・モデルの生成物はローカルに保持し、公開JSONには匿名ケースID・ハッシュ・採点・件数だけを出す。

## 受入条件と限界

形式・Python必須ケースは全通過。モデル評価では出典捏造0、無断本文変更0、確定世界法則の誤否定0、意味の異なる量の無条件換算0、指定外の大幅な監修拡大0を必要条件とする。

起動の暫定目標は肯定・否定それぞれ90%以上。少数ケースの目標で、一般的精度ではない。未実施なら達成としない。代表の科学判断は人が根拠を読んで確認する。fixtureの正答をスキル本文へ埋め込まず、観測した失敗に対して一般的な改善を行う。
